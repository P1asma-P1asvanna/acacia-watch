# Acacia Watch: คู่มือขึ้นเว็บจริง

ใช้ Python 3.8 ขึ้นไป โครงสร้างโปรเจกต์ดูที่หัวข้อ "โครงสร้างไฟล์" ด้านล่าง
- รันในเครื่อง: ไม่ต้องติดตั้งอะไรเพิ่ม เก็บข้อมูลเป็นไฟล์ SQLite
- ขึ้นเว็บจริง: ตั้งตัวแปร `DATABASE_URL` เพื่อใช้ PostgreSQL (เช่น Neon) ต้องติดตั้ง `psycopg` ผ่าน `requirements.txt` (Render ติดตั้งให้เองตอน build)

---

## ทางที่แนะนำ: GitHub + Render + Neon (ฟรีทั้งหมด)

### ขั้นที่ 1: เก็บโค้ดไว้บน GitHub
1. สมัคร/เข้าสู่ระบบ github.com แล้วสร้าง repository ใหม่ ตั้งเป็น **Private**
2. กด **Add file → Upload files** แล้วลากโฟลเดอร์และไฟล์ทั้งหมดขึ้นไป (`backend/`, `frontend/`, `tools/`, `render.yaml`, `Dockerfile`, `.gitignore`, `README.md`) — หรือใช้ `git push` จาก VS Code ก็ได้ แล้วกด Commit
3. **ห้ามเอารหัสผ่านฐานข้อมูลใส่ไฟล์ใดบน GitHub** (ในขั้นถัดไปจะใส่ที่ Render เท่านั้น)

### ขั้นที่ 2: สร้างฐานข้อมูลบน Neon
1. สมัคร neon.com สร้างโปรเจกต์ใหม่ (เลือกภูมิภาคใกล้ผู้เล่น เช่น สิงคโปร์)
2. ในหน้า Dashboard กดปุ่ม **Connect** แล้วคัดลอก **Connection string** ที่ขึ้นต้นด้วย `postgresql://` (ใส่รหัสผ่านมาให้แล้ว)
3. เก็บไว้ชั่วคราว เดี๋ยวใช้ในขั้นที่ 3 ไม่ต้องสร้างตารางเอง เซิร์ฟเวอร์สร้างให้ตอนเริ่มทำงานครั้งแรก

### ขั้นที่ 3: ขึ้นเซิร์ฟเวอร์บน Render
1. สมัคร render.com แล้วผูกกับบัญชี GitHub
2. กด **New → Blueprint** เลือก repository ที่สร้างไว้ Render จะอ่าน `render.yaml` ให้
   (หรือกด **New → Web Service** เลือก repo, Runtime = Python, Build Command = `pip install -r backend/requirements.txt`, Start Command = `python backend/server.py`, Plan = Free, Health Check Path = `/healthz`)
3. ตอนที่ถามค่า `DATABASE_URL` ให้วาง Connection string จาก Neon
4. ตัวแปรเหล่านี้ต้องมี: `DD_COOKIE_SECURE=1` และ `DD_TRUST_PROXY=1` (ใน `render.yaml` ใส่ไว้แล้ว ถ้าสร้างแบบ Web Service ให้เพิ่มเอง)
5. รอ Deploy เสร็จ แล้วเปิดที่อยู่ `https://ชื่อ.onrender.com`
6. **สมัครบัญชีแรกทันที** บัญชีแรกจะเป็นผู้ดูแล (ถ้าปล่อยไว้ คนอื่นอาจสมัครตัดหน้าได้) จากนั้นส่งลิงก์ให้ผู้เล่นสมัครบัญชีเอง

อัปเดตเว็บภายหลัง: แก้ไฟล์บน GitHub แล้ว Commit Render จะ deploy ใหม่เอง

### ข้อจำกัดของแผนฟรี
- Render หลับหลังไม่มีคนใช้ 15 นาที ตื่นช้าราว 1 นาที วิธีแก้เบาๆ: ให้ GM เปิดเว็บทิ้งไว้ก่อนเริ่มเล่น 1-2 นาที
- Neon หลับหลังไม่มีการใช้ 5 นาที คนแรกที่ใช้อาจรอเพิ่มเล็กน้อย
- ถ้าอยากให้ตื่นตลอด: ใช้บริการตรวจเว็บฟรี (เช่น UptimeRobot หรือ cron-job.org) ตั้งให้เปิด `https://ชื่อ.onrender.com/healthz` ทุก 5-10 นาที (ชั่วโมงฟรีของ Render 750 ชม./เดือน พอสำหรับเว็บเดียวที่เปิดตลอด) ปล่อยให้ Neon หลับต่อไป เพราะ `/healthz` ไม่แตะฐานข้อมูล

## ตัวแปรที่ตั้งได้
| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `DATABASE_URL` | ใช้ PostgreSQL ตามที่อยู่นี้ | ไม่ตั้ง = ใช้ SQLite |
| `DD_DB` | ที่เก็บไฟล์ SQLite (เมื่อไม่ตั้ง DATABASE_URL) | `backend/acacia_watch.sqlite3` |
| `PORT` | พอร์ต | 8080 (Render ตั้งให้เอง) |
| `HOST` | ที่อยู่ที่ฟัง | 0.0.0.0 |
| `DD_COOKIE_SECURE=1` | ใช้เมื่อเปิดผ่าน https (บนเว็บจริงควรเปิดเสมอ) | ปิด |
| `DD_TRUST_PROXY=1` | ใช้เมื่ออยู่หลัง reverse proxy ของคุณเอง | ปิด |

## รันทดลองในเครื่อง
```
python3 backend/server.py
```
เปิด http://localhost:8080

## ทางเลือกอื่น
- **VPS:** อัปโหลดไฟล์ รัน `python3 backend/server.py` ด้วย systemd ใส่ Caddy/nginx ด้านหน้าเพื่อทำ https ใช้ SQLite ได้ (ตั้ง `DD_DB` ไปที่โฟลเดอร์ที่สำรองข้อมูลไว้)
- **Docker:** `docker build -t acacia-watch .` แล้ว `docker run -d -p 8080:8080 -v dd-data:/data acacia-watch` (หรือส่ง `-e DATABASE_URL=...` เพื่อใช้ Postgres)
- **Render แบบเสียเงินพร้อมดิสก์ถาวร:** ผูกดิสก์ไปที่ `/data` ใช้ SQLite เดิมได้เลย ไม่ต้องใช้ Neon

## รหัสผ่านผู้ดูแลหาย
รันบนเครื่องที่ตั้งค่าเดียวกับเซิร์ฟเวอร์ (บน Render ใช้แท็บ Shell ของบริการ ซึ่งอาจเป็นฟีเจอร์ของแผนเสียเงิน ถ้าไม่มี ให้รันในเครื่องตัวเองโดยตั้ง `DATABASE_URL` เป็นของ Neon)
```
python3 backend/server.py list-users
python3 backend/server.py reset-password ชื่อผู้ใช้
python3 backend/server.py make-admin ชื่อผู้ใช้
```
ผู้ดูแลตั้งรหัสใหม่ให้ผู้เล่นได้จากหน้าข้อมูลผู้เล่น (ช่อง "รหัสผ่านใหม่")

## ย้ายข้อมูลจากเว็บเวอร์ชันเก็บในเบราว์เซอร์
1. เวอร์ชันเดิม: ตั้งค่าเว็บ → สำรองข้อมูล → ดาวน์โหลดไฟล์ .json
2. เว็บใหม่: สมัครบัญชีแรก (ผู้ดูแล) → ตั้งค่าเว็บ → นำเข้า → เลือกไฟล์
บัญชีเดิมของผู้เล่นใช้รหัสผ่านเดิมได้ (ระบบแปลงเป็นรูปแบบที่ปลอดภัยกว่าตอนล็อกอินครั้งแรก)

## สำรองข้อมูล
- ในเว็บ: ตั้งค่าเว็บ → สำรองข้อมูล (ไม่รวมรหัสผ่าน) ควรทำเป็นประจำ
- Neon: มีระบบกู้คืนย้อนหลังตามแผนของบริการ ดูในเมนู Backup/Restore ของโปรเจกต์
- SQLite: ก็อปปี้ไฟล์ฐานข้อมูลเก็บไว้

## สิ่งที่เซิร์ฟเวอร์บังคับให้ (กันโกง)
- รหัสผ่านแฮช PBKDF2 ที่เซิร์ฟเวอร์ คุกกี้ HttpOnly ล็อกอินผิดซ้ำถูกชะลอ
- ผู้เล่นเห็น/แก้ได้เฉพาะตัวละครของตัวเอง ตัวละคร GM และห้อง Adventure เป็นของผู้ดูแล
- HP สูงสุดและ AC ถูกคำนวณซ้ำที่เซิร์ฟเวอร์ทุกครั้งที่บันทึก ผู้เล่นตั้งโหมดพิมพ์เองไม่ได้
- ผู้เล่นยังปรับเลเวล ค่าพลัง และเพิ่มไอเท็ม/เกราะเองได้ ผู้ดูแลควรตรวจดู

## ข้อจำกัดตอนนี้
- แคตตาล็อก/ตั้งค่า/ห้อง ใช้หลักการ "บันทึกล่าสุดชนะ" ถ้าผู้ดูแลสองคนแก้พร้อมกัน
- ผู้เล่นเห็นข้อมูลที่ผู้ดูแลแก้เมื่อสลับหน้าหรือกลับมาเปิดหน้าเว็บ ยังไม่อัปเดตสดอัตโนมัติ

## อัปเดตสด (Live updates)

เมื่อมีคนบันทึกอะไร คนอื่นที่เปิดเว็บอยู่จะเห็นภายในไม่ถึงวินาที (ไม่ต้องรีเฟรช) หลักการ: เซิร์ฟเวอร์เก็บเลขเวอร์ชันในหน่วยความจำ เบราว์เซอร์ถาม `/api/poll?v=N` ค้างไว้ได้สูงสุด ~25 วินาที (ไม่แตะฐานข้อมูล จึงไม่ปลุก Neon) พอเลขเปลี่ยนก็ตอบทันที แล้วหน้าเว็บโหลดข้อมูลใหม่
- ไม่วาดหน้าใหม่ถ้าข้อมูลไม่ต่างจากเดิม และไม่แตะหน้าจอขณะมีคนกำลังพิมพ์/แก้ฟอร์ม (รอจนพิมพ์เสร็จค่อยอัปเดต)
- แท็บที่ถูกซ่อน (สลับไปแอปอื่น เช่น Owlbear) จะหยุดถามเอง และกลับมาโหลดข้อมูลล่าสุดทันทีที่เปิดกลับมา
- ตัวแปรสภาพแวดล้อม `DD_POLL_SECONDS` (ค่าเริ่มต้น 25) ปรับเวลาค้างคำถามได้

## ผู้เล่นเห็นห้อง Adventure

ผู้เล่นมีเมนู Adventure (อ่านอย่างเดียว) เห็นเฉพาะห้องที่ตัวละครของตัวเองนั่งอยู่ ลำดับ Initiative แบบสด รอบ และเทิร์นปัจจุบัน/ถัดไป พร้อมแถบ "ถึงตาของคุณแล้ว" และ HP ของตัวเอง เซิร์ฟเวอร์ตัดข้อมูลก่อนส่ง (`store.py → player_rooms`) จึงไม่มี HP/ค่าสถานะของ NPC หรือคนอื่น และเห็นเฉพาะรายการที่ทอย Initiative แล้ว

## ค่าที่เป็นของส่วนกลาง กับของแต่ละคน

- **ส่วนกลาง (ผู้ดูแลแก้ ทุกคนเห็นเหมือนกัน):** ชื่อเว็บ, สโลแกน, โลโก้, ภาพปก เก็บเป็นค่า `site`
- **ของแต่ละคน (ผู้เล่นและผู้ดูแลตั้งเองได้ที่เมนู Site settings):** สีทั้งหมด (รวมสีขอบเมนูซ้ายและสีไฮไลท์เทิร์น), เอฟเฟกต์ปุ่ม, มุมโค้ง, ฟอนต์, จำนวนแถวต่อหน้าของข้อมูลเกม เก็บที่เซิร์ฟเวอร์แยกตามบัญชี (`prefs:<id>`) จึงตามไปทุกเครื่องที่ล็อกอิน
- ค่าเริ่มต้นของสีอยู่ที่ `THEME_DEF` ใน `frontend/js/04-server-mode.js`

## รูปตกแต่ง (อัปโหลด)

กติกาแสดงใต้ช่องอัปโหลดทุกช่อง และเซิร์ฟเวอร์ตรวจซ้ำอีกครั้ง (ตัวเลขชุดเดียวกันอยู่ใน `backend/acacia/config.py` และ `frontend/js/19-images.js`)

| ช่อง | ของใคร | ด้านสั้นต่ำสุด / สูงสุด (ตอนใช้) | ไฟล์เข้า | ไฟล์หลังย่อ | GIF |
|---|---|---|---|---|---|
| โลโก้ | ส่วนกลาง (admin) | 64 / 64 px | ≤ 1 MB | ≤ 200 KB | ≤ 1 MB, ด้านยาว ≤ 512 px |
| ภาพปก | ส่วนกลาง (admin) | 480 / 800 | ≤ 5 MB | ≤ 450 KB | ≤ 2 MB, ≤ 1280 px |
| พื้นหลัง | ของแต่ละคน | 480 / 800 | ≤ 5 MB | ≤ 450 KB | ≤ 2 MB, ≤ 1280 px |
| พื้นหลังกล่อง | ของแต่ละคน | 256 / 256 | ≤ 3 MB | ≤ 300 KB | ≤ 1 MB, ≤ 800 px |
| ไอคอนสถานะ | ส่วนกลาง (admin) | 128 / 6000 → ย่อให้เหลือไม่เกิน 512 | ≤ 2 MB | ≤ 150 KB | ≤ 1 MB, ≤ 512 px |
| ของตกแต่ง | ของแต่ละคน | 64 / 64 | ≤ 1 MB | ≤ 200 KB | ≤ 1 MB, ≤ 512 px |

- ไฟล์เล็กกว่า 1 KB หรือด้านยาวเกิน 6000 px จะถูกปฏิเสธ รูปนิ่งถูกย่อเป็น WebP ในเบราว์เซอร์ก่อนส่ง
- โควตา: ผู้เล่น/admin คนละ 6 รูป รวม 3 MB ส่วนของส่วนกลาง (โลโก้ ภาพปก ไอคอนสถานะ) 60 รูป รวม 10 MB รูปไม่ถูกใช้นาน 10 นาทีจะถูกลบเอง
- รูปเป็นของเจ้าของบัญชีเท่านั้น คนอื่นแก้หรือลบไม่ได้ และการตั้งค่าของใครไม่กระทบคนอื่น
- GIF เก็บตามต้นฉบับ (ไม่ย่อ) ถ้าปิดแอนิเมชันในการตั้งค่า หรือเครื่องตั้ง "ลดการเคลื่อนไหว" จะแสดงเฟรมแรกแทนเพื่อไม่ให้กระตุก

## โหมดจัดวาง (ลากกล่อง)

ปุ่ม "จัดวาง" มีในหน้า ชีทตัวละคร, Players, Site settings และห้อง Adventure กดแล้วลากที่จับ ⠿ (เมาส์/นิ้ว) หรือใช้ปุ่ม ↑ ↓ ซ่อน และ ↔/½ (ครึ่งความกว้าง ไม่มีในห้อง Adventure) ได้ ลำดับเก็บแยกตามบัญชี (`prefs.lay`) จึงตามไปทุกเครื่อง และไม่กระทบคนอื่น ปุ่ม "คืนค่าเดิม" ล้างเฉพาะหน้านั้น

## สถานะ (Conditions)

- ผู้เล่นและ GM เปิดดูได้ที่เมนู "สถานะ (Conditions)" (อ่านอย่างเดียว แตะชื่อเพื่อดูผลของสถานะ)
- GM แก้ไข เพิ่ม ลบได้ที่ ข้อมูลเกม → แท็บ Conditions (ช่อง: ชื่อ, ชื่อไทย, สรุปสั้น, รายละเอียด) ปุ่ม "คืนค่าเริ่มต้น" ในแท็บนี้จะกลับเป็นรายการ 15 สถานะมาตรฐานของ 5e
- ผู้เล่นแก้ไม่ได้ เซิร์ฟเวอร์ปฏิเสธการเขียนแคตตาล็อกจากบัญชีผู้เล่น และเมื่อ GM บันทึก ผู้เล่นเห็นทันทีโดยไม่ต้องรีเฟรช
- ไอคอนและสี: ใน ข้อมูลเกม → Conditions แต่ละสถานะอัปโหลดไอคอนได้ (ภาพใหญ่จะถูกย่อให้ไม่เกิน 512×512 อัตโนมัติ) และเลือกสีได้ สีใช้กับชื่อสถานะ และไฮไลท์ชื่อนั้นเมื่อถูกพิมพ์อยู่ในคำอธิบายของสถานะอื่น กดไฮไลท์แล้วจะเด้งการ์ดอธิบาย (ปิดด้วย ✕ หรือ Esc)
- ในช่องรายละเอียดพิมพ์ `**ข้อความ**` เพื่อทำตัวหนาเอียงแบบหัวข้อย่อย
- เฉพาะ admin อัปโหลดไอคอนได้ เซิร์ฟเวอร์ตรวจว่าไอคอนเป็นรูปที่อัปโหลดไว้จริงและสีเป็น #rrggbb เท่านั้น

### กฎของสถานะ (Rules)

ที่ ข้อมูลเกม → Conditions → แก้ไข ส่วน "ผลของสถานะ" (ชื่อไทยของสถานะถูกเอาออกแล้ว)

**ระดับสถานะ:** ระยะเวลา (Turn/Round/นาที/ชั่วโมง) · เมื่อได้รับซ้ำ (ไม่ซ้อน / ต่ออายุ / ซ้อนหลายอัน / เป็นระดับพร้อมระดับสูงสุด) · จบสถานะเมื่อ Short rest, Long rest, โดนดาเมจ, ได้รับการรักษา

**กฎ** (สูงสุด 20 ข้อ ข้อละ 8 ผลต่อฝั่ง) = เมื่อ… → (ทอยตรวจหรือไม่ก็ได้) → ถ้าผ่าน… / ถ้าไม่ผ่าน…
- **เมื่อ:** ตลอดเวลา · ได้รับสถานะ · สถานะจบ · เริ่ม/จบ Turn หรือ Round (ทุก N อัน) · Turn/Round สุดท้ายของระยะเวลา · โดนดาเมจ · ได้รับการรักษา · ทอยโจมตี · ถูกโจมตีโดน · เคลื่อนที่ · ใช้ Action · พัก (Short/Long)
- **ทอยตรวจ:** Saving Throw (ค่าพลัง + DC) · Ability check (ค่าพลังหรือทักษะ + DC) · d20 เทียบ DC · ทอยลูกเต๋าใดๆ ต้องได้ ≥ เป้าหมาย
- **ผล:** รับดาเมจ · ฟื้น HP · Temp HP · เปลี่ยน HP สูงสุด · ได้รับสถานะอื่น (กำหนดระยะเวลาเองได้) · ลบสถานะ (นี้ / อื่นทั้งหมด / ระบุ) · เปลี่ยนระยะเวลาที่เหลือ · เปลี่ยนระดับสถานะ · Advantage/Disadvantage · บวก/ลบค่าที่ทอย (เช่น -1d4 โจมตี) · เปลี่ยนค่าพลัง · เปลี่ยนความเร็ว (แยกเดิน/บิน/ว่าย/ปีน) · เปลี่ยน AC · ต้านทาน/ภูมิคุ้มกัน/อ่อนแอต่อดาเมจ · ข้อจำกัด (ใช้ Action ไม่ได้, ขยับ/พูด/ร่ายเวทไม่ได้, พลาด Save อัตโนมัติ ฯลฯ) · ข้อความเอง
- ทำซ้ำกฎได้ ระบบแปลงกฎเป็นประโยคอ่านง่ายให้เอง (ไทย/อังกฤษ) แสดงที่หน้า Conditions และการ์ดอธิบายของทุกคน
- ตอนนี้กฎเป็นข้อมูลอ่านอย่างเดียว (ยังไม่ถูกคำนวณในตัวติดตาม Initiative) เซิร์ฟเวอร์เก็บเฉพาะคำที่รู้จัก (`backend/acacia/conditions.py`) และแปลงกฎรูปแบบเก่าให้อัตโนมัติ
- สถานะมาตรฐาน 15 อย่างมีกฎตั้งต้นให้ (แก้/ลบได้)

## สถานะในการต่อสู้ (Initiative) และปุ่ม HP

ในห้อง Adventure → Initiative (GM เท่านั้น) แต่ละตัวมีแถวควบคุมใต้ชื่อ:
- **ดาเมจ / ฮีล / Temp HP:** พิมพ์จำนวนแล้วกดปุ่ม ดาเมจหัก Temp HP ก่อน แล้วค่อยหัก HP เลือกประเภทดาเมจได้ ระบบคิด ต้านทาน (ครึ่งหนึ่ง) / ภูมิคุ้มกัน (0) / อ่อนแอ (สองเท่า) ตามสถานะที่ตัวนั้นติดอยู่ ตัวละครจากชีทจะถูกแก้ HP ในชีทจริง (ผู้เล่นเห็นสด) ส่วนศัตรูที่พิมพ์ชื่อเองมี HP ของตัวเอง
- **ติดสถานะ:** เลือกสถานะ ระบุระยะเวลาเองหรือใช้ค่าเริ่มต้นของสถานะ ป้ายสถานะ (ไอคอน สี ระดับ เวลาที่เหลือ) แสดงข้างตัวนั้นทั้งฝั่ง GM และผู้เล่น (ผู้เล่นเห็นเฉพาะชื่อ เวลาที่เหลือ และระดับ) กดป้ายเพื่อดูคำอธิบายและกฎ GM ลบสถานะหรือปรับระดับได้
- **นับเวลาอัตโนมัติ:** ระยะเวลาแบบ **Turn** ลดลง 1 เมื่อจบตาของตัวที่ติดสถานะ ส่วนแบบ **Round** ลดลง 1 เมื่อจบรอบ (ทุกคนเล่นครบ) ไม่ใช่เมื่อจบตาตัวเอง สถานะที่หมดเวลาหายเอง ส่วนสถานะที่ตั้ง "จบเมื่อโดนดาเมจ / ได้รับการรักษา" หายเมื่อเกิดเหตุการณ์นั้น ติดสถานะกลาง Round นับรอบที่ค้างอยู่เป็น 1 รอบ
- **ไฮไลท์ "มีผลตอนนี้":** ทุกครั้งที่กด Turn ถัดไป ป้ายสถานะของตัวที่เพิ่งถึงตา (และของทุกตัวเมื่อขึ้น Round ใหม่) จะมีขอบเรืองกับป้าย ● มีผลตอนนี้ พร้อมกล่อง "เกิดอะไรขึ้นตอนนี้" สรุปเป็นประโยค (ถึงตาใคร, ขึ้น Round ไหน, สถานะไหนหมดเวลา) ผู้เล่นเห็นกล่องเดียวกันและมีคำอธิบาย "อ่านสถานะยังไง?"
- **รอตัดสิน:** เมื่อถึงเวลาตามกฎของสถานะ (เริ่ม/จบ Turn หรือ Round ทุก N, Turn สุดท้าย, ได้รับ/จบสถานะ, โดนดาเมจ, ได้รับการรักษา) ระบบวางกฎไว้ในกล่อง "รอตัดสิน" ให้ GM กด "ทอยให้" (บวกค่า Save/ทักษะของตัวละครจากชีท ศัตรูที่พิมพ์เองบวก 0) หรือเลือก ผ่าน/ไม่ผ่านเอง หรือข้าม ผลที่ระบบทำให้ได้: ดาเมจ ฮีล Temp HP ติด/ลบสถานะ เปลี่ยนเวลา/ระดับ ผลอื่นๆ (Advantage, ความเร็ว, AC ฯลฯ) ถูกบันทึกในบันทึกเหตุการณ์ให้ GM ทำเอง
- กฎแบบทอยโจมตี / ถูกโจมตีโดน / เคลื่อนที่ / ใช้ Action ไม่เกิดเอง มีปุ่ม ⚡ ที่ตัวนั้นให้ GM กดเรียกกฎ
- **บันทึกเหตุการณ์** (GM เท่านั้น) เก็บ 40 รายการล่าสุด ปุ่ม "← Back" ย้อนเฉพาะตัวชี้ Turn ไม่ย้อนผลของสถานะหรือ HP

## Feats (กฎ D&D 2024)

- **ข้อมูลเกม → Feats**: GM เพิ่ม/แก้/ลบได้ ฟิลด์: ชื่อ, หมวด (Origin / General / Fighting Style / Epic Boon), เลเวลขั้นต่ำ, เงื่อนไข, พลังที่ +1 ได้ (เช่น `str,dex`), เลือกซ้ำได้, รายละเอียด มีรายชื่อชุด 2024 ให้เป็นค่าเริ่มต้น (รายละเอียดส่วนใหญ่ว่าง GM เติมเองได้ — ใส่ของ 2014 เองได้เช่นกัน)
- **อาชีพ**: ฟิลด์ "เลเวลที่ได้ ASI/Feat" (เริ่มต้น 4,8,12,16,19 ; Fighter 4,6,8,12,14,16,19 ; Rogue 4,8,10,12,16,19)
- **Background**: ฟิลด์ "Origin Feat ที่ได้" แสดงบนชีตอัตโนมัติ
- **ชีตตัวละคร → ASI และ Feats**: แต่ละเลเวลที่ถึงเลือก ASI (+2 ตัวเดียว หรือ +1 สองตัว) หรือ Feat; มีช่อง "Feat เพิ่มเติม" สำหรับ Fighting Style / Feat ซ้ำ / GM มอบให้
- ค่าพลังที่กรอกยังเป็นค่าพื้นฐาน ระบบบวกโบนัสให้เอง (สูงสุด 20, Epic Boon สูงสุด 30) แล้วใช้ทุกที่: modifier, HP, AC, โจมตี, Saves/Skills, Initiative; เซิร์ฟเวอร์คำนวณตรงกัน
- ถ้าลดเลเวลจนต่ำกว่าเลเวลที่เลือก ASI โบนัสนั้นจะไม่ถูกนับ (ข้อมูลที่เลือกไว้ยังอยู่)

### Feats — อัปเดต
- **สีโบนัสจาก Feats/ASI**: ตัวเลข modifier ที่ถูกบวก, "= ค่ารวม" ใต้ช่องพลัง, Initiative/Passive ที่ได้จาก Feat ใช้สีของตัวเอง (ค่าเริ่มต้นเขียวมิ้นต์) เปลี่ยนได้ที่ ตั้งค่าเว็บ → "สีโบนัสจาก Feats/ASI"
- **ASI**: แต่ละเลเวลเลือก "+2 ให้พลังเดียว", "+1 ให้สองพลัง" หรือ Feat; Feat ที่ตั้ง "แต้มพลัง = 2" (เช่น Ability Score Improvement) เลือก +1 ได้สองช่อง (เลือกพลังเดียวกันสองช่อง = +2)
- **เอฟเฟกต์ของ Feat (ข้อมูลเกม → Feats)**: เพิ่มได้หลายอัน — โบนัส Initiative (ค่าคงที่ และ/หรือ + Proficiency Bonus), HP สูงสุด (ต่อเลเวล/ครั้งเดียว), AC (ตลอดเวลา/เฉพาะตอนสวมเกราะ), Passive Perception พร้อมข้อความสรุป; และเพดานค่าพลัง (20 หรือ 30)
- ค่าเริ่มต้น: Alert = Initiative + Proficiency Bonus, Tough = HP +2 ต่อเลเวล, Defense = AC +1 เมื่อสวมเกราะ; Origin Feat ของ Background นับรวมให้อัตโนมัติ
- เอฟเฟกต์ **Speed (ft)**: บวกเข้ากับช่อง Speed ในชีต (แสดงเป็นชิป Speed สีโบนัส ค่าที่พิมพ์ไว้ยังเป็นค่าพื้นฐาน) Speedy มี +10 เป็นค่าเริ่มต้น
- **หน้า Feats** (เมนูซ้าย): ทุกคนอ่านได้ ค้นหาตามชื่อ กรองตามหมวด เปิดดูรายละเอียดและเอฟเฟกต์; GM กดปุ่มไปแก้ในข้อมูลเกมได้

## Rest (พักผ่อน)
- **ชีตตัวละคร → HP**: ปุ่ม "พักสั้น: ทอย Hit Die" ใช้ Hit Die 1 ลูก ทอย d(ลูกเต๋าอาชีพ)+CON ฟื้น HP และนับ Hit Dice ที่ใช้; ปุ่ม "พักยาว" ฟื้น HP เต็ม ลบ Temp HP คืน Hit Dice ครึ่งหนึ่ง (อย่างน้อย 1) และเคลียร์ Death saves
- **Adventure → Initiative**: ปุ่ม Short rest / Long rest ของทั้งกลุ่ม — ลบสถานะที่ตั้ง "จบเมื่อพักสั้น/ยาว", เรียกกฎ "เมื่อพัก" ของสถานะเข้าคิว (เลือกชนิดการพักในกฎได้ เช่น Exhaustion ลดระดับตอน Long rest), และตอน Long rest ฟื้น HP เต็มให้ทุกตัว (ตัวละครในชีต และศัตรู custom ที่มี HP)

## เวทมนตร์ (Spells)
- **ข้อมูลเกม → Spells**: GM เพิ่มเวทเอง (ชื่อ, เลเวล 0 = Cantrip, สำนัก, เวลาร่าย, ระยะ, องค์ประกอบ, ระยะเวลา, Concentration, Ritual, อาชีพ, รายละเอียด) ค่าเริ่มต้นเป็นรายการว่าง
- **ชีตตัวละคร → เวทมนตร์**: คำนวณ Spell Save DC / โจมตีด้วยเวทจากพลังร่ายเวทของอาชีพ; Spell Slots ตามชนิดอาชีพ ("Full Caster", "Half Caster", "Third Caster" ที่ช่อง "ประเภทการร่ายเวท" ของอาชีพ) และ Pact Magic ของ Warlock; กดจุดเพื่อทำเครื่องหมาย Slot ที่ใช้แล้ว
- เพิ่มเวทจากข้อมูลเกมหรือพิมพ์ชื่อเอง, ติ๊ก "เตรียมไว้", ปุ่ม "ร่าย" เลือก Slot (ร่ายระดับสูงกว่าได้) และตัด Slot ให้ ถ้าเวทต้อง Concentration จะแสดงแถบสมาธิ (ร่ายเวทใหม่จะเลิกสมาธิเก่า)
- โดนดาเมจขณะมีสมาธิ: แจ้งเตือนให้ทอย CON save DC สูงกว่าของ 10 หรือดาเมจ/2; HP เป็น 0 เสียสมาธิอัตโนมัติ
- พักยาว (ปุ่มบนชีต หรือ Long rest ในหน้า Initiative) คืน Slot ทั้งหมดและเลิกสมาธิ; พักสั้นใน Initiative คืน Pact slots (บนชีตมีปุ่ม "พักสั้นเสร็จ: คืน Pact slots")
- ตารางจำนวน Slot ตามเลเวลฝังอยู่ที่ `frontend/js/11c-spells.js` (Half Caster ใช้ตาราง 2024 ที่เริ่มมี Slot ตั้งแต่เลเวล 1)

### Spells — School / Casting time / Duration เป็นตัวเลือก
- **School**: เลือกจากสำนักทั้ง 8 (ค่าเดิมที่พิมพ์เองยังคงอยู่ในตัวเลือก)
- **Casting time**: Action, Bonus Action, Reaction, Minute(s), Hour(s), Special — มีช่องจำนวน (ขึ้นเมื่อเลือกนาที/ชั่วโมง) และช่องหมายเหตุเพิ่มเติม (เช่น เงื่อนไขของ Reaction)
- **Duration**: Instantaneous, Round(s), Minute(s), Hour(s), Day(s), Until dispelled, Special — จำนวนและหมายเหตุเหมือนกัน; ถ้าติ๊ก Concentration จะต่อข้อความ "Concentration, up to ..." ให้อัตโนมัติ
- ข้อความสำเร็จรูปแสดงใต้ช่องเลือกทันที และเวทที่บันทึกไว้ก่อนหน้า (พิมพ์เป็นข้อความ) จะถูกแปลงเป็นตัวเลือกให้เอง

## ทอยเต๋าร่วมกัน + หน้า Spells (อ่านอย่างเดียว)

- **ทอยเต๋าร่วมกัน**: แท็บเต๋าในห้อง (GM) และแผงเต๋าบนหน้าห้องของผู้เล่น ทุกคนในห้องเห็นผลทอยของทุกคนทันที (เซิร์ฟเวอร์เป็นคนทอย แก้ผลไม่ได้) รองรับ d4–d100, จำนวนลูก, ค่าบวก/ลบ, Advantage/Disadvantage (ลูกที่ไม่ถูกเลือกขีดฆ่า), ช่อง "ทอยเพื่ออะไร", ทอย 20 ติดขอบแสดงสีเขียว/แดง
- ผู้เล่นต้องมีตัวละครนั่งอยู่ในห้องนั้นถึงจะทอยได้ (ไม่งั้นขึ้นข้อความแจ้ง)
- **หน้า Spells**: เมนู Spells ทุกคนเข้าได้ ค้นหาตามชื่อ กรองตามเลเวล/สำนักเวท ผู้เล่นแก้ไขไม่ได้ แอดมินมีปุ่มไปแก้ใน Game data → Spells
